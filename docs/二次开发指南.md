# BabelSim 二次开发指南：新增求解器与物理模型

本文说明如何在不破坏现有 Mesh/Field/Operator/Assembly/Solver/MPI 边界的前提下，
利用 BabelSim 开发新的 PDE 或物理模型。以标量对流-扩散方程为例：

```text
∂(ρT)/∂t + div(ρ U T) = div(Γ grad(T)) + S
```

Heat、组分输运和被动标量都可从同一模式开始。关键原则是：新增物理代码组合已有
抽象，而不是让已有抽象认识新的物理变量。

## 1. 修改范围

一个新求解器通常只需新增：

```text
src/physics/advection_diffusion/
├── solver.cpp                 # 方程组装与迭代流程
└── solver.h                   # 若该求解器需要独立公开接口

src/io/advection_diffusion_case_reader.cpp  # 仅在有专属物性/控制时新增
cases/<新案例>/
├── case.bs
├── mesh/
├── fields/initial/
├── physics/
├── numerics/
└── output.bs
```

还需要：

1. 在 `Makefile` 的 `SOURCES` 中加入实现文件；
2. 在 `src/apps/babelsim_solve.cpp` 增加一个直接分派分支；
3. 为新 case 的 `solver` 写入唯一名称，例如 `advectionDiffusionFoam`；
4. 在 `tests/` 加入制造解、边界条件、串行/MPI 回归。

不应修改 Mesh、Field、HaloExchange、SparseAssembly、LinearSolver 或
`babelsim-post`，除非新需求确实需要新的通用数学能力，而不是单一物理模型的便利
函数。

当前启动器刻意使用简单的 `if` 分派：

```cpp
if (definition.solver == "simpleFoam") {
    return runSimpleFoam(definition, parallel, arguments.time_name);
}
if (definition.solver == "advectionDiffusionFoam") {
    return runAdvectionDiffusion(definition, parallel, arguments.time_name);
}
throw std::runtime_error("未知 BabelSim 求解器: " + definition.solver);
```

在求解器数量很少时，这比额外的 Manager/Factory/Registry 更清晰。只有当分派逻辑
确实变成维护瓶颈时，才考虑小型函数表。

## 2. 定义 Field，而不是定义物理专属存储

使用通用 `ScalarField`、`VectorField` 和 `TensorField`：

```cpp
struct AdvectionDiffusionFields {
    explicit AdvectionDiffusionFields(const Mesh& mesh)
        : temperature(mesh, FieldLocation::Cell, "T"),
          velocity(mesh, FieldLocation::Cell, "U"),
          face_flux(mesh, FieldLocation::Face, "phi") {}

    ScalarField temperature;
    VectorField velocity;
    ScalarField face_flux;
};
```

`temperature` 不需要继承 `Field<double>`，也不需要把边界条件写进求解器。案例中的
`T.field` 负责 initial value 和各 patch 的 FixedValue、ZeroGradient、Symmetry 等
数学条件。若 `U` 是给定流场，仍然只是从 `U.field` 读取的普通 `VectorField`。

在 MPI 下，先读取全局场定义，再用 `decompose()` 构造局部网格并按 global ID 复制到
local Field。现有启动器中的 `localize()` 展示了这一步。所有 cell Field 都是
`owned + ghost` 的连续数组；代数系统只对 `owned_cells` 产生行。

## 3. 用通用算子组装方程

推荐把每一物理方程的装配写成短小、直接的函数：

```cpp
void assembleTemperature(
    ScalarEquation& equation,
    const AdvectionDiffusionFields& fields,
    double density,
    double diffusivity,
    const Methods& methods,
    double dt,
    const ScalarField* previous,
    const ScalarField* older)
{
    equation.reset();
    if (methods.time != TimeMethod::Steady) {
        addTimeDerivative(
            equation, *previous, dt, density, methods.time, older);
    }
    addConvection(
        equation, fields.face_flux, fields.temperature, methods.convection,
        methods.interpolation, methods.gradient);
    addDiffusion(equation, diffusivity, fields.temperature,
                 methods.gradient, methods.diffusion);
}
```

瞬态分支应先检查 `previous != nullptr`，并在 BDF2 时传入 `older`。实际求解器可将
`dt/previous/older` 包装为该物理模型自己的轻量状态，但不应复制对流、扩散、LDU 面
系数或非正交修正的实现。固定源项直接加到 `equation.source[cell]`；若源项有
隐式线性部分，则同时修改 `diagonal[cell]`。

装配前后的 MPI 顺序必须显式：

```cpp
halo.exchange(fields.temperature);
halo.exchange(fields.velocity);
flux(fields.velocity, fields.face_flux, methods.interpolation);
halo.exchange(fields.face_flux);
assembleTemperature(equation, fields, rho, gamma, methods, time);
```

算子不自行通信，避免在内部循环隐式触发 collective；这样同一算子可用于串行、MPI、
稳态和瞬态流程。

## 4. 装配与线性求解

单方程求解器应持有可复用对象：

```cpp
SparseAssembly assembly(mesh);
PreparedLinearSolver serial_solver(config);
std::unique_ptr<DistributedLinearSolver> distributed_solver;
ScalarEquation equation(mesh);
Eigen::VectorXd rhs(mesh.ownedCellCount());
Eigen::VectorXd solution(mesh.ownedCellCount());
```

每次迭代执行：

1. `assembly.update(equation)` 更新预分配矩阵值；
2. `assembleSource(equation, rhs)` 生成 owned RHS；
3. 首次调用 `compute()`，以后调用 `factorize()`；
4. 串行调用 `PreparedLinearSolver::solve()`，MPI 调用
   `DistributedLinearSolver::solve()`；
5. 将 `solution[mesh.ownedIndex(cell)]` 写回 owned Field；
6. `halo.exchange(field)`，供下一次算子使用。

不要把 ghost cell 当作未知量写入 Eigen 矩阵。跨 rank 的 face 系数由
`DistributedLinearSolver` 的 halo matvec 加入；这正是通用 MPI 代数层存在的原因。

## 5. 何时新增专用算子

默认优先使用 Gradient、Divergence、Convection、Diffusion、Flux、Interpolation 和
TimeDerivative。只有算法具有稳定、独立、不可读地由基础算子表达的数值语义时，才在
`src/physics/<模型>/` 新增专用组件。

当前的两个例子是：

- `MomentumInterpolation`：同位网格上的 Rhie-Chow 面通量；
- `PressureCorrection`：压力修正方程、速度修正与面通量修正的一致算法单元。

对三维非正交网格，优先使用 `interpolation = Corrected`、
`gradient = LeastSquares` 和 `diffusion = Corrected`。扩散项的矩阵仍是正交紧凑
LDU，非正交通量通过 `integratedNormalGradient()` 显式加入右端；网格角度较大时
可选 `LimitedCorrected`。专用算子不应重新计算面中心、面积向量或非正交分解，
而应直接调用该通用接口。这样同一求解器不需要区分二维和三维，也不需要复制 MPI
halo 数据结构。

专用组件仍应接收通用 Mesh/Field/Equation/Method/ParallelContext，不应建立自己的
网格、场容器或 MPI 缓冲体系。不要把 SIMPLE 的每个小步骤拆成类，也不要仅为命名而
创建一次性 wrapper。

## 6. 设计 case 文件

新案例的 `case.bs` 仅选择求解器和文件位置：

```text
solver advectionDiffusionFoam
mesh mesh/channel.mesh
fields fields/initial
physics physics/advection_diffusion.bs
numerics numerics/advection_diffusion.bs
output output.bs
```

物性读取器应把文本映射为小型值类型，例如 `density`、`diffusivity`、`source`；
数值读取器映射为 `Methods`、时间步长和 `LinearSolverConfig`。解析只在启动时发生，
求解循环不可访问文件路径或字符串字典。

若复用 `U.field`、`T.field`、已有 mesh 和 `output.bs`，后处理器无需改动：它从
metadata 识别 field 名称、类型和位置，并按 global ID 合并 CSV。

## 7. 并行与输出检查表

新增求解器进入 MPI 后，逐项检查：

- 所有被读取的 cell 输入场是否在读取 ghost 前调用 `halo.exchange()`；
- 方程是否只对 `owned_cells` 生成矩阵行与 RHS；
- 全局 residual、范数、质量守恒和收敛判断是否使用 `ParallelContext::sum/max`；
- 是否只对 owned cell 写结果；
- 1/2/4 rank 结果是否按 global ID 比较，并使用明确的绝对/相对容差；
- 是否避免在每个迭代步创建大型 Field、稀疏拓扑或通信索引。

通用结果写出示例：

```cpp
const auto time_directory = case_root / output.directory / output.time_name;
writeOwnedFieldCsv(time_directory, fields.temperature, parallel);
writeOwnedResultMetadata(time_directory, mesh, parallel, output.time_name, {
    {"T", "scalar", FieldLocation::Cell},
    {"U", "vector", FieldLocation::Cell},
});
```

## 8. 最小测试集

为每个新模型至少加入：

1. 单元测试：常量场、线性场、边界条件和制造解；
2. 串行回归：残差收敛、守恒量和可比较的解析/基准结果；
3. 非正交网格回归：验证 corrected diffusion 或相关几何算子；
4. MPI 回归：1/2/4 rank 的 global ID 覆盖与数值容差比较；
5. 后处理检查：`babelsim-post` 生成的 VTK/Tecplot 文件包含正确实体数和字段值。

若这些测试都通过，新物理模型便是在既有框架上扩展，而不是重新实现一套求解器基础。
