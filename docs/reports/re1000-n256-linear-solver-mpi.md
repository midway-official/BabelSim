# Re=1000、256×256 腔体的线性后端与 MPI 吞吐测试

测试日期：2026-09-06。此报告比较的是同一个稳态 SIMPLE 问题在不同线性后端和 MPI
进程数下达到同一**外层吞吐判据**的墙钟时间，不是 Ghia 精度或网格无关性验证。

## 条件与方法

- Case：[benchmark-re1000-n256](../../cases/cavity/benchmark-re1000-n256/)；二维退化三维
  结构化网格 `256×256×1`，共 65,536 个 cell，双曲正切壁面加密系数为 1.5；
  `Re=1000`。
- 对流为二阶 `linearUpwind`；梯度为最小二乘；面插值为线性中心；扩散为正交中心格式。
- Release 构建使用 `-O3 -march=native -flto=auto -ffast-math`。主机为 AMD Ryzen AI MAX+ 392
  （12 个物理核心）；每次只运行一个作业，使用 1、2 或 4 个 MPI rank。
- 五种方案都使用相同的松弛系数（速度 0.30、压力 0.25）、外层质量不平衡阈值
  `1e-8`、速度变化阈值 `3e-3`，以及线性绝对/相对阈值 `1e-10/3e-3`。每一运行的根 rank
  以 `/usr/bin/time` 记录墙钟与 RSS。

`3e-3` 的线性相对阈值是为分区 ILUT 设计的吞吐设置：分区后局部 ILUT 的强度下降，
`1e-4` 会让部分健康的线性系统耗尽 1000 次内迭代。所有下表结果最终均满足质量不平衡
阈值；但不同内层残差会改变 SIMPLE 外迭代数，因此不能把本表当成不同方案间的高精度
流场等价性证明。

基线的速度方程使用 `BiCGSTAB+ILUT`，压力校正方程使用
`CG+IncompleteCholesky`。这是 CG 的合理使用方式：压力校正近似对称正定，含对流的
速度矩阵一般并非对称。`CG+ILUT` 不被框架接受，也不作为测试项。

## 热点剖析

对每种单-rank方案另行使用 `-O3 -pg` 构建并运行同一 Case。`gprof` 的插桩构建只用于
函数时间占比，不与上表 release 时间混用。Eigen 的高度内联模板会在 `gprof` 调用图中
形成一个 `PreparedLinearSolver` 归因环；它不表示每次 Krylov 步真的重新构造 Solver。
下表将该归因环合并回对应的 Krylov/ILUT 路径。

| 方案 | 主要热点（`gprof` 单 rank） | 含义 |
|---|---|---|
| 基线 | CG+Incomplete Cholesky 81.3%；IC 因子化 2.8%；最小二乘梯度 2.2% | 压力校正的 CG 求解明显压过其他工作；应先减少压力线性求解成本。 |
| BiCGSTAB+ILUT | BiCGSTAB/ILUT 调用树约 68%（其中显式 BiCGSTAB 14.4%，ILUT 因子化 10.4%）；梯度 3.8% | 局部 ILUT 和稀疏 Krylov 工作是主导，但外迭代最少，绝对时间最低。 |
| GMRES(30)+ILUT | GMRES Arnoldi 25.1%，ILUT 因子化 10.4%，其余主要为 ILUT 内联求解归因环；梯度 4.2% | Arnoldi 正交化、30 维基和更多外迭代增加时间与内存，未换来收敛优势。 |
| BiCGSTAB+AMG | AMG V-cycle 52.4%，粗层 SparseLU 2.6%，Galerkin 1.7%，BiCGSTAB 2.3% | 层级平滑、限制/延拓和粗层求解是绝对主导。 |
| GMRES(30)+AMG | AMG V-cycle 49.3%，GMRES Arnoldi 4.2%，粗层 SparseLU 2.9%，Galerkin 2.1% | AMG 仍是瓶颈；GMRES 比 BiCGSTAB 多出 Krylov 基与正交化成本。 |

所有方案的通用 FVM 几何/离散工作远小于线性代数：最小二乘梯度约 2–4%，对流/扩散
组装分别处于低个位数百分比。故当前应优先优化线性预条件、稀疏 matvec 和通信，而不应为
了本算例先改写上层 `Field`、`eqn` 或 SIMPLE 算法。

## MPI 行为与解释

ILUT 两组从 1 到 4 rank 保持正向强缩放：子域内 ILUT 三角求解和稀疏计算仍占主要成本，
4 rank 后效率约 51–62%。基线在 4 rank 的外迭代增加至 321，故速度比低于统一
BiCGSTAB+ILUT。

AMG 两组在 2/4 rank 反而变慢或接近不变。当前 AMG 是“每个 rank 的局部聚合 V-cycle”
预条件器：它不建立全局粗网格。划分后，每 rank 仍需要 halo 矩阵向量乘和 Krylov 全局归约，
同时局部层级对跨子域低频误差的削弱变差；`amgRefreshInterval=8` 已降低层级重建频率，
但无法消除这些同步和局部粗层成本。因此这不是 MPI 正确性问题，而是局部 AMG 的预条件
质量与通信开销在 256² 强缩放下的自然限制。

## 结论和下一步

1. 当前 256² Re=1000 吞吐任务建议优先 `BiCGSTAB+ILUT`，以 4 rank 作为本主机上的
   经济并行点；不应仅因 AMG 名称而默认选择 AMG。
2. 若压力精度需要显著收紧，应重新单独进行 `1e-4` 或更严残差、ILUT fill/drop 参数和
   流场差异的验证；不能外推本表的吞吐配置。
3. AMG 后续优化方向是分布式全局粗层、聚合通信压缩、pipelined Krylov 或更大问题的弱缩放；
   不应把 MPI 通信逻辑上推到 SIMPLE 或通用算子层。
4. `gmres ilut` 现已由后端正式支持，串行与分布式扩散回归均覆盖该组合。它提供了稳定的
   方案比较基准，但本算例中不优于 BiCGSTAB+ILUT。
