# 分布式线性后端与性能观测优化报告

本报告记录 2026-09-06 完成的线性后端优化及其回归证据。修改限定在 Field 的内部
halo 状态、默认 Eigen/MPI 计算后端、代数求解器、应用生命周期观测、测试和文档；
`src/physics` 没有修改，`eqn/math/solve`、离散前端以及 Heat、Transport、稳态/瞬态
SIMPLE 的编程接口保持不变。

## 1. 性能指标的定义

日志同时给出两种不能相互替代的指标：

- `timeToSolution`：从应用入口、MPI 初始化、Case 构造和求解开始，到成功结果写出、
  Case 析构完成为止，各 rank 墙钟时间的最大值；不包含随后执行的 `MPI_Finalize`。
- `runtimeElapsed`：RunTime 构造到性能快照之间各 rank 耗时的最大值，不包含最终结果
  写出。固定外迭代测试用它衡量同等计算工作量的吞吐。

`BabelSim performance` 还报告线性求解次数、Krylov 迭代、SpMV、halo、逻辑
Allreduce、方程装配、预条件准备和应用的次数与耗时。MPI 日志对每项取所有 rank 的
最大值，避免把 rank 0 的局部耗时误作并行关键路径。`linearSeconds` 包含该线性求解内的
SpMV、halo、归约和预条件应用；AMG 的 `preconditionerApply` 也包含 V-cycle 内部的
SpMV、halo 和粗网格归约。因此这些子项会重叠，不能相加后当成总时间。

串行运行中的 `allreduce` 是算法执行的逻辑全局点积/范数次数；单 rank 时它退化为本地
复制，不发生 MPI 通信。所有 SpMV 数据均由实际计算核计数，包括串行 AMG 各层 V-cycle，
不再按 Krylov 迭代数估算。

## 2. 实施内容

### 2.1 BiCGSTAB 与分布式 SpMV

- BiCGSTAB 把一轮末尾的残差范数和下一轮 `rho` 合并到同一个全局归约；停止条件仍使用
  全局量，所有 rank 执行相同分支和相同迭代次数。
- 分布式 SpMV 预先把本地矩阵分成内部行和分区边界行。每次乘法先投递非阻塞 halo，
  计算内部行，再等待通信并计算边界行和跨分区 face 系数。
- Krylov halo 只打包分区边界 owned 值，不再为每次 SpMV 复制完整的
  `owned + ghost` Field。稀疏模式、通信索引和缓冲均在准备期建立并复用。
- 所有新增 MPI 调用均通过统一返回码检查；非阻塞请求的生命周期完整限制在一次 SpMV 内。

### 2.2 Field halo 有效性

Field 增加私有 halo 有效标记。常量填充和按几何位置求值会生成完整一致的本地布局；
场赋值、缩放和逐点乘积按输入有效性传播状态。任何内部可写存储借用都会使 halo 失效，
计算后端完成交换后再标记有效。连续 `math` 操作因而不会重复同步同一个未变化输入。

该标记不属于 Solver API。Physics 仍把 Field 看作一个完整数学场，不知道 ghost、版本、
缓冲或通信过程。

### 2.3 分布式 AMG

旧的“每个 rank 独立做局部 AMG”已删除。当前 MPI AMG：

1. 在 distributed fine operator 上做加权 Jacobi 平滑；
2. 依据稳定 global cell ID 建立跨 rank 一致的结构化聚合；
3. 将各 rank 的局部 `P^T A P` 贡献归约成同一个小型全局粗矩阵；
4. 归约粗网格残差，各 rank 求解相同粗系统，再把校正延拓到本地 owned 行；
5. 用当前完整分布式算子做后平滑。

完整细网格矩阵从不集中或复制。粗矩阵在各 rank 复制并直接分解，当前最多 2048 行；
这使实现适合当前单节点、小到中等进程数基础，但不是面向大规模集群的完全分布式多层
coarse solve。串行路径保留强连接聚合的多层 AMG；MPI 路径当前是“分布式细层 + 全局
聚合粗层”的两层实现，因此二者的 Krylov 迭代数不能直接等同。

AMG 只能作为 CG/BiCGSTAB 的预条件器，独立 AMG 求解模式已经删除。GMRES 的枚举、配置、
工作区、实现和现行案例均已删除；解析器会明确拒绝旧的 `gmres` 和独立 `amg` 配置。

## 3. 测试环境与配置

- CPU：AMD Ryzen AI MAX+ 392，12 个物理核、24 个逻辑线程；
- 使用 1、2、4 个 MPI rank，每 rank 固定 `OMP_NUM_THREADS=1`；
- 发布构建：`-O3 -march=native -flto -ffast-math`；
- Case：`cases/cavity/benchmark-re1000-n128`；
- 网格：`128 x 128 x 1`，双曲正切壁面加密，Re=1000；
- 离散：最小二乘梯度、线性面插值、二阶线性迎风对流、正交扩散；
- 线性阈值：绝对 `1e-10`、相对 `1e-4`、最多 1000 次；
- AMG：最多 12 层、粗空间目标 48、一次平滑、每 8 次方程更新刷新。

自然收敛测试使用 `continuityTolerance=1e-8`、`velocityTolerance=8e-4`。固定工作量测试
把两个外层阈值设为 `1e-30`，并把 `maxIterations` 固定为 200。后者恰好完成 200 次后
按设计返回状态码 2，不写“成功结果”；它是吞吐测量，不是收敛或精度验收。

## 6. 热点结论

1. **ILUT 的主要热点是局部三角求解。** 固定单 rank 中预条件应用占线性求解约 75.7%，
   预条件准备另占 runtime 约 15.6%。分区会缩小本地 ILUT，但 Krylov/外迭代由 86.5
   增至 111.0，说明块预条件质量随子域缩小而下降。
2. **AMG 减少了串行 Krylov 次数，但 V-cycle 的实际工作量大。** 单 rank 固定运行只有
   12.23 次 Krylov/外迭代，却执行 103082 次各层 SpMV；这正是实际内核计数的价值。
3. **MPI AMG 当前受平滑通信限制。** 2/4 rank 固定运行约有 9 万次 SpMV、halo 和
   Allreduce，约为 ILUT SpMV 的两倍。全局粗校正降低了最终时间，但继续扩展 rank 时，
   细层 Jacobi 的 halo 与粗残差归约会成为首要瓶颈。
4. **4 rank 的归约不可忽略。** ILUT 固定运行的 `allreduceSeconds=0.469 s`，AMG 为
   `0.370 s`；由于计时重叠，这些值不与 linearSeconds 相加，但已表明下一步应减少同步点，
   而不是继续微调装配循环。
5. **本题已经获得正强缩放，但规模仍偏小。** 固定 AMG 的 runtime 1 到 4 rank 加速
   3.06 倍，效率 76.4%；不能据此外推到多节点或大规模三维问题。

## 7. 架构与正确性验收

- Physics/Solver 没有性能计数、MPI、halo 或代数实现调用；架构门禁新增规则，禁止
  `src/physics` 使用 `PerformanceCounters`、`performance()` 或 `reportPerformance()`。
- FVM 数值前端仍只通过 `ComputeBackend` 的粗粒度接口请求同步、归约和离散方程求解。
- 分布式 AMG、SpMV、Krylov 工作区和 MPI 请求全部留在代数/默认后端；Field 仅保存私有
  有效状态，Solver 无法访问。
- 解析扩散系统验证 BiCGSTAB+ILUT 和 BiCGSTAB+AMG；MPI 测试额外检查每次分布式 SpMV
  恰好对应一次 Krylov halo，以及融合后的归约次数上界。
- 公开 `math` 的污染 halo 回归覆盖 1/2/4 rank，并确认有效输入不会被连续重复同步。
- 小腔体 SIMPLE 在 1/2/4 rank 均严格停止于 137 次，中心速度均为 `-0.149236`；Heat
  1/2 rank 最大温差为 `1.46e-12`。这些是正确性证据，独立于本报告的宽松吞吐 Case。
